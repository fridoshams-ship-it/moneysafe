# MoneySafe — смарт-контракты MVP

Сейф от самого себя: пользователь блокирует актив до выбранной даты, деньги лежат в Aave V3 и приносят доход. **Досрочного вывода нет. Штрафов нет. Изменить дату нельзя.** В дату открытия владелец забирает всё: вложенное плюс доход.

## Как устроено

- **MoneySafeFactory** — создаёт сейфы. На каждый сейф разворачивается отдельный контракт (минимальный прокси EIP-1167), поэтому деньги разных людей никогда не смешиваются.
- **MoneySafeVault** — один сейф: владелец, актив, дата открытия. Сразу отправляет средства в Aave V3 (`supply`), в дату открытия отдаёт всё владельцу (`withdraw`).

### Что может владелец фабрики (админ MoneySafe)
1. Разрешить актив (`allowAsset`) — адрес aToken берётся из самого Aave, ошибиться нельзя.
2. Запретить актив для **новых** сейфов (`disallowAsset`).
3. Поставить на паузу **новые** депозиты (`setDepositsPaused`).

### Чего не может никто, включая админа
- Вывести деньги из чужого сейфа.
- Открыть сейф раньше даты.
- Перенести дату.
- Остановить вывод из сейфа.

У контракта сейфа нет ни одной админской функции. Передача прав на фабрику — в два шага (`Ownable2Step`).

## Функции для приложения

| Действие | Вызов |
|---|---|
| Создать сейф | `factory.createVault(asset, amount, unlockTime, goal)` — перед этим `approve` на фабрику (в Account Abstraction оба вызова идут одной операцией) |
| Пополнить сейф | `factory.topUp(vault, amount)` — дата не меняется; пополнить может любой (подарок), деньги всё равно принадлежат владельцу |
| Забрать в дату | `vault.withdraw()` — только владелец, только после `unlockTime` |
| Список сейфов | `factory.vaultsOf(user)` |
| Данные сейфа | `vault.balance()`, `vault.earned()`, `vault.principal()`, `vault.unlockTime()`, `vault.timeLeft()`, `vault.isUnlocked()` |

Ограничения срока: от 1 дня до 10 лет.

## Тесты

```bash
npm install --legacy-peer-deps
npx hardhat test
```

12 тестов: создание, запрет вывода даже за секунду до даты, выплата с доходом, запрет вывода чужим и админу, повторный вывод, пополнение, неверные данные, пауза только депозитов, права админа, защита от повторной инициализации, изоляция сейфов, пауза Aave.

## Развёртывание

```bash
AAVE_POOL=0x... ASSETS=0xUSDC,0xUSDT,0xWETH,0xWBTC OWNER=0xMultisig \
  npx hardhat run scripts/deploy.js --network <сеть>
```

Адреса Aave Pool и токенов берите только из официальной адресной книги Aave (`bgd-labs/aave-address-book`) для выбранной сети. Владелец фабрики — мультисиг (Safe), не личный кошелёк. Сеть добавьте в `hardhat.config.js`.

## Что сделать до основной сети

1. **Аудит.** Контракт держит деньги людей. Без независимого аудита в основную сеть не выпускать.
2. Тест на форке реальной сети с настоящим Aave (сейчас тесты идут на модели Aave).
3. ETH принимается как WETH: приложение оборачивает ETH перед депозитом.
4. USDT в некоторых сетях требует сброса `approve` в ноль — контракт использует `forceApprove`, это учтено.
5. Если Aave временно остановит выводы, `withdraw` вернёт ошибку, и его можно повторить позже. Сейф при этом не теряет средства — это проверено тестом.
6. Восстановление доступа: владелец сейфа — адрес кошелька пользователя. Приложение должно давать экспорт ключа, иначе при потере доступа к входу деньги останутся в сейфе.
